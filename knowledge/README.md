# 项目知识库

这里是 Watermark Remover 的仓库内 Harness：用 Markdown 记录稳定约定、重构进度、重要决策和开发过程，供人和不同编码工具接续工作。它不替代代码、Git 历史或实际测试结果。

## 从哪里开始

1. 读 [当前状态](state/CURRENT.md)，了解当前阶段和下一个动作。
2. 按任务查看下面对应的文档；无需一次读完整个知识库。
3. 完成工作后，只更新事实确实改变的文档。

| 想知道什么 | 位置 |
| --- | --- |
| 用户流程、输出应满足什么 | [产品契约](contracts/product.md) |
| 前后端与模型服务各负责什么 | [架构契约](contracts/architecture.md) |
| UI/UX 设计系统、beUI 组件与零覆盖铁律 | [设计规范](../DESIGN.md) |
| 重构阶段、顺序和验收条件 | [路线图](roadmap.md) |
| 新模型如何做同口径图像对照并生成 HTML | [模型评测流程](model-evaluation.md) |
| 当前做到哪里、下一步是什么 | [当前状态](state/CURRENT.md) |
| 为什么做出长期有效的选择 | [决策记录](decisions/) |
| 某次实施与验证实际发生了什么 | [开发日志](logs/) |

## 记录规则

- **契约**写已确认的产品与架构边界；**路线图**写计划；**当前状态**只写现在的位置，不积累流水账。
- 重要且会持续影响后续实现的选择，单独写一份有编号的决策记录。普通实现细节留在代码和 Git 中。
- 一次有实质结果的开发工作可写一篇 `logs/YYYY-MM-DD-topic.md`：目标、实际改动、验证、剩余问题。小改动无需为填日志而建文件。
- 引用可核对的文件、提交或官方资料；把“计划”“已实现”“已验证”分开表述。不写入 API Key、凭证或私人原图。
- 同一事实只保留一个维护位置；其他文档通过链接引用。过时内容直接修订或标明被哪项决策取代。
