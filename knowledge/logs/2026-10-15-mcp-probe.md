# Grok Bot MCP 免费兼容探针

日期：2026-10-15。范围：为个人 Grok Bot 桌面应用准备可真实连接的远程 MCP 探针，验证认证、图片与 ZIP、耗时兼容性；未开放正式图片处理或小红书工具。

## 实现与本地验证

- 复用已加入工作区的官方 `go-sdk v1.7.0`，提升为直接依赖并补齐传递依赖。新增 `internal/mcpprobe`，挂到现有 Go `/api/mcp`，复用现有 HTTPS 代理。
- 配置 `MCP_TOKEN_SHA256` 启用，空值关闭，非法摘要阻止启动。SDK Bearer 中间件验证凭据，项目仅提供摘要恒定时间比较；与网页 GitHub 会话隔离，不发布 OAuth discovery。
- 四个工具：`probe_ping`、`probe_echo_image`、`probe_test_files`、`probe_wait`。图片原字节回传附摘要，固定 PNG/ZIP 通过 MCP 内容与资源交付，不落盘；等待限制 0–300 秒、并发一个，支持上下文取消和可选进度。协议与请求大小限制由 SDK 处理。
- 针对 `internal/mcpprobe`、`internal/config`、`internal/server` 的 race 测试及 vet 通过；测试包括 SDK HTTP 客户端发现/调用、图片字节和摘要、PNG/ZIP 完整性、认证关闭及隔离、等待取消、日志无凭据/图片、旧版初始化穿过现有中间件。Linux amd64 构建通过，未运行全仓测试或付费模型。
- 操作和客户端验收的唯一说明为 [MCP.md](../../apps/server/MCP.md)，包括安全凭据交接、资源 URI、文件内容注入和待实测耗时。未创建尚未验收的产品工作流 Skill。

用户授权直接操作 `com.anysphere.sand`，并在安全卡前确认保存专用 Token。通过桌面 UI 在 Anastasya 对话中完成安全输入、发送测试任务、上传测试图片和保存 Bot 交付的文件；未将原文 Token 放进聊天。11:50–11:57（Asia/Shanghai）的聊天报告、附件 UI、保存后的文件与服务端脱敏方法日志共同作为证据。

| 项目 | 路径与结论 |
| --- | --- |
| 连接和认证 | 已连接 `personal-mcp`，原生工具发现和 ping 成功。Bot 实际采用其云端电脑的 stdio → `mcp-remote 0.15.1` → 远程 HTTPS，不能记录为直接 `url + headers` 连接已验收 |

| 真实聊天附件输入 | 本机上传 128×128 PNG，Bot 从附件落盘文件生成 data URL 文件，经 `$file:` 注入原生 `probe_echo_image`；返回 ImageContent 并交付附件。保存回本机后逐字节与输入一致，45,310 字节，SHA-256 为 `acc3f45703a20ec4e9d94f775747c0afa72ad70b4c3cd8126837bed958d979cf` |

Bot 报告之所以使用 stdio 桥接，是其 AddMcpServer 一等工具不能通过 `$file:` 直接注入安全卡秘密。实际入口为 `bash /home/box/agent-tools/personal-mcp-stdio.sh`；脚本从 `/home/box/agent-tools/personal-mcp-auth.txt` 读取认证并启动 mcp-remote。配置细节来自 Bot 报告，未直接读取其云端文件。认证文件最初报告为 0644，已要求收紧；11:57:12 Bot 确认 stat 为 0600、owner box:box，未读取内容或更改其他配置。

本机验收原图、保存的回传 PNG 和 ZIP 位于 Git 忽略的 `.local/mcp-probe/grok-artifacts/`。后续业务接入需适配原生长调用超时与资源读取入口差异；可考虑任务提交/查询及工具可调用的文件交付方式。进度是否延长客户端超时、取消传播、大图参数体积和直接 HTTPS 安全凭据配置仍未独立验收；不继续扩大本轮探针测试。
