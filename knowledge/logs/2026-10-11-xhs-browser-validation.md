# 小红书匿名浏览器与媒体下载对照

## 目标和方法

继续[第一轮 HTTP 验证](2026-10-08-xhs-feasibility.md)，区分“请求跳转登录页”与“浏览器不能取得笔记图片数据”。Windows Computer Use 因无法可靠确认 Chrome URL 被工具停止，未操作用户的 Chrome。随后使用可用的 Codex 内置浏览器控制接口进行独立对照，全程没有执行账号登录、读取登录凭据或关闭登录限制。

从用户此前提供的前两条长链接读取页面。两条页面均加载了笔记标题、图集数量及 INITIAL_STATE 中对应笔记的完整 imageList；出现登录弹窗不等于图片数据未加载。通过浏览器的开发者读取能力只提取笔记标识、类型、标题、图片尺寸和媒体 URL。

将提取的笔记字段暂存于 Git 忽略的 `.local/xhs-verification/`，复用现有 HTTP 探针的图片候选提取、地址验证及媒体下载函数。用于衔接既有探针的页面数据输入由浏览器字段构造，**不计为 HTTP 笔记解析成功**。不新增产品功能或浏览器依赖。

## 实测结果

| 样本 | 浏览器图集数量 | 预览下载 | 候选 JPEG 下载 | 候选实际尺寸 |
| --- | --- | --- | --- | --- |
| 又该踏上新的冒险了… | 7 | 7/7 | 7/7 | 2 张 1707×2560；5 张 4000×6000 |
| 薄荷波点♡ | 2 | 2/2 | 2/2 | 1910×2546、2236×2992 |

预览格式为 WebP、宽度为 1080；候选资源是 JPEG，尺寸高于预览。第一条页面声明的尺寸均为 1707×2560，不能替代下载文件的实际尺寸。

两条笔记共下载 18 个文件（9 个预览、9 个候选），全部经 Pillow `load()` 完整解码。制作并检查逐图左右对照，两个版本构图对应；9 张候选图片在本轮视觉检查中未发现平台附加的可见水印。不证明是作者上传的原始文件，也不保证不存在隐藏水印或其他笔记同样可用。

另外对浏览器最终的 `/explore/<id>` 路径和对应分享参数做了两次匿名 HTTP 对照，仍均跳转 `/login`，未取得目标笔记。因此不能靠简单切换长链接路径解决当前 HTTP 限制，也没有证据将成功归因于某个浏览器参数或某项指纹设置。

## 结论和后续边界

**本机“浏览器读取笔记数据 → HTTP 下载候选图片”链路已在两条图文笔记上验证可行。** 这修正了只有第一轮 HTTP 失败证据时的判断，尚不能视为可直接部署的解析服务。

本轮只验证了 2/5 条用户样本，两条均为多图；单图、真实短链、其余三条与云端均未验收。私人字段、下载文件、对照图和解码报告位于 `.local/xhs-verification/browser-2026-10-11/`，没有保存或提交完整页面、账号凭据。

下一步优先在用户腾讯云的独立临时环境验证匿名浏览器解析和媒体下载，确认服务器出口是否可用；需要服务器接入信息。不将桌面内置浏览器的成功直接外推为 Playwright 无头浏览器在服务器上也成功。验证成功后再决定正式浏览器解析模块及其部署方式，当前不增加页面、正式 API 或 ZIP。
