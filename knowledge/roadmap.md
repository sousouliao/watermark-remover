# Watermark Remover 重构路线图

更新日期：2026-09-23

## 目标与范围

保留“上传图片 → 移除水印 → 对比结果 → 下载”的产品目标，重构现有以手绘蒙版和 IOPaint-LaMA 为中心的实现。新版通过火山方舟托管 API 同时支持 **Doubao Seedream 5.0 Lite** 和 **Doubao Seedream 5.0 Flash**；用户可以明确选择模型，后续依据真实样本的效果、耗时和费用决定默认模型。

本轮重构完成后，不再依赖 IOPaint、LaMA 服务或常驻 GPU。沿用现有 Vue 3 前端和 NestJS 后端，除非实施时出现直接阻碍，不为重构而更换框架或拆出新包。自动检测水印、账户与计费、多云路由、自部署模型不在本轮范围内。

## 模型与产品约定

| 模型 | 接入定位 | 待确认事项 |
| --- | --- | --- |
| Seedream 5.0 Lite | 已有的同系列对照模型 | 方舟控制台当前可用的模型 ID、输入限制与实际价格；文档中可见 `doubao-seedream-5-0-260128` 和 `doubao-seedream-5-0-lite-260128` 两种写法，不直接假定它们在当前账号下等价 |
| Seedream 5.0 Flash | 新模型，优先验证速度与局部编辑效果 | `doubao-seedream-5-0-flash-260915` 的开通状态、输入限制、实际价格与响应格式 |

两款模型均按**图像编辑模型**接入，不能把当前黑白蒙版直接当作其原生 inpainting mask。手绘信息可转成标记图或其他经官方接口验证可用的区域指示。模型生成结果也不能天然保证非目标区域像素不变。

新版提供两种操作路径：

1. **直接移除**：上传后选择模型，发送原图和明确的去水印指令，无须先画蒙版。
2. **指定区域**：用户在原图上标出水印，模型根据区域指示编辑；如需将局部结果贴回原图，必须先确认尺寸、对齐和边缘过渡可靠。

结果页保留原图对比与下载，并显示本次使用的模型。两种操作路径都允许用户查看结果后返回编辑或切换模型重试。

## 阶段与验收

### 0. 核对 API 与建立样本集

执行 Issue：[#1](https://github.com/sousouliao/watermark-remover/issues/1)

- 在方舟控制台确认两款模型均可调用、模型 ID、鉴权、图像输入与输出格式、尺寸限制、单次费用及超时行为。
- 准备约 20～30 张有使用权的真实样本，覆盖角落小字、半透明水印、大块 Logo、人物/文字/复杂纹理上的遮挡；保留原版 LaMA 结果作为可选对照。
- 用相同图片和指令分别测试 Lite 与 Flash，记录水印残留、非目标区域变化、耗时、费用和失败原因；测试无区域指示与有区域指示两种请求。

**完成条件**：两款模型各有成功的图像编辑调用；记录可复现的请求格式和限制；明确哪些样本需要指定区域。若某模型在当前账号不可调用，先记录阻碍，不以猜测的参数开始产品接入。

### 1. 重构后端调用链

执行 Issue：[#2](https://github.com/sousouliao/watermark-remover/issues/2)

- 将现有 `/api/watermark/remove` 的 IOPaint 专用请求改为统一的去水印请求：原图、模型选择、操作模式，以及指定区域模式所需的区域数据。
- 在服务端集中处理方舟鉴权、模型 ID 映射、输入校验、超时、错误转换和输出图片；API Key 仅留在服务端环境变量中。
- 两个模型共用同一套调用与响应逻辑，只在经过验证确有差异的参数上分支。响应继续提供可供前端展示和下载的图片，并返回实际模型信息。
- 调用成功、鉴权失败、参数错误、上游超时和无有效图片等情况有明确响应；不自动用另一款付费模型重试。

**完成条件**：通过同一个后端接口，明确选择 Lite 或 Flash 都能处理图片；失败时用户能得到可理解的错误；前端无需知道方舟密钥或上游响应结构。

### 2. 重构前端编辑流程

执行 Issue：[#3](https://github.com/sousouliao/watermark-remover/issues/3)

- 将上传后的主操作改为“选择模型 → 直接移除”，保留原有蒙版编辑器作为“指定区域”入口。
- 整理图片与笔画的坐标、缩放和导出逻辑，使手绘标记在原图尺寸下位置正确；按阶段 0 验证的方式制作模型输入。
- 统一处理进行中、失败、结果对比、切换模型重试和下载状态；避免切换图片或模型后显示旧结果。
- 保留现有上传格式、结果对比和移动端基本可用性。只有在编辑器现有实现阻碍区域定位时，才抽离其绘制逻辑；不预先建设跨框架编辑器包。

**完成条件**：用户从同一页面可用任一模型完成直接移除和指定区域移除，并能对比、重试、下载；区域标记与原图位置一致。

### 3. 清理旧实现并完成交付

执行 Issue：[#4](https://github.com/sousouliao/watermark-remover/issues/4)

- 删除已不再使用的 IOPaint 配置、请求字段、依赖和说明，更新 README、环境变量示例及本地启动说明。
- 用阶段 0 的样本再跑两模型对照，重点检查非水印区域是否被改动、输出尺寸/比例和细节质量；决定默认模型，另一款保持可选。
- 运行与改动对应的前后端构建、类型检查和核心流程验证；核对部署环境中的密钥、费用控制及请求超时配置。

**完成条件**：本地与目标部署环境均可完成“上传 → 两模型之一处理 → 对比 → 下载”；旧 IOPaint 服务不再是运行依赖；README 与实际操作一致。

## 决策规则

- **先看保真，再看速度和费用**：去水印成功但改动人脸、文字或背景的结果不算成功。
- **不预设 Flash 一定优于 Lite**：官方发布说明中的“更快、更便宜”不能代替本项目的真实样本结果；Flash 的具体价格以当前方舟控制台为准。
- **先做完整可用链路，再做局部优化**：指定区域若不能稳定控制修改范围，就保留清晰的结果预览和重试，不宣称“像素级无损”。
